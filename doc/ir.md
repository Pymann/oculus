# Oculus IR and facts: data format (draft)

This is the data format between the frontend and the rules. It is derived from what
the rules of the catalogue (`Pymann/coding-rules`, `catalog/`) need, not from what
Clang happens to offer. The frontend is not part of this document: whatever binds
to Clang later has to produce exactly this, and nothing in here refers to Clang
types or pointers. Nothing is final.

Input for the design: the 435 rules, their `needs` tokens, their descriptions
(`rules.d/`) and especially their `good` examples, which list the cases a naive
checker reports wrongly. Section 9 checks the format against representative rules.

## 1. Principles

1. **Frontend independent.** The IR holds Oculus' own ids, enums and strings. No
   pointer into a Clang AST, no Clang enum values. A rule written against the IR runs
   unchanged whether the IR comes from C or C++, and from whatever binding is chosen.
2. **Immutable.** The worker builds the IR of one TU once; afterwards nothing changes
   it. Analyses (CFG, data flow, metrics) are computed from it and stored next to it,
   also immutable, so the thread pool can read everything without locks.
3. **Tables, not object graphs.** Every kind of entity is a table of records with a
   dense integer id per TU (`FileId`, `TokenId`, `MacroId`, `TypeId`, `DeclId`,
   `NodeId`, `BlockId`). References are ids. That makes the IR serialisable as is
   (worker process to analysis process, and to the phase 2 store), cheap to copy, and
   easy to index.
4. **Where something comes from is always recorded.** Most false positives of the old
   `exodus analyze` came from code that the user did not write in that place: macro
   expansions, system headers, template instantiations, implicit code. Every node
   therefore carries an `Origin` (section 2.3) and two positions (spelling and
   expansion). Rules filter by origin; they never guess it from text.
5. **The rule says what it needs.** The `needs` tokens of the catalogue map to the
   layers below. The scheduler builds only the layers the enabled rules need for a TU
   (no CFG if no `cfg` rule is on).

## 2. Common parts

### 2.1 Positions

```
Loc      { file: FileId, line: u32, col: u32 }        # 1-based, col in bytes
Range    { begin: Loc, end: Loc }                      # end is exclusive
SrcPos   { spelling: Range, expansion: Range, macro: MacroExpId? }
```

- `spelling` is where the characters are written; `expansion` is where the code
  takes effect (the macro call site). For code not produced by a macro both are equal
  and `macro` is empty.
- Findings use the position a rule chooses, by default `expansion.begin`. The
  catalogue tests (`expected.txt`, `file:line:col`) are compared against it.

### 2.2 Files

```
File     { id, path, kind: source|header|system_header|interface_header,
           language: c|cpp, standard: c90..c23|cpp98..cpp23,
           lines: [LineClass], hash }
LineClass  blank | comment | code | code_and_comment
```

- `kind` comes from the include search path (system) and from `oculus.json`
  (interface headers, see `catalog/CONCEPTS.md` in coding-rules).
- `lines` is Oculus' own line classification, used by the size metrics (OC-0380,
  OC-0387, OC-0388). Code inside `#if 0` is `code` (the rules measure what the
  reader sees).

### 2.3 Origin

Every token, declaration, statement and expression carries a bit set:

| flag | meaning | typical rule that must not fire on it |
|---|---|---|
| `in_system_header` | spelled in a system header | almost all rules |
| `from_macro` | produced by a macro expansion (`SrcPos.macro` set) | OC-0382 complexity, operand rules on `assert` |
| `from_macro_arg` | spelled in a macro argument, so the user wrote it at the call site | rules that do apply to arguments |
| `implicit` | generated by the compiler (implicit constructors, conversions, `this`) | OC-0282 marked_override on implicit destructors |
| `instantiated` | belongs to a template instantiation, not the written template | duplicate findings per instantiation |
| `in_unevaluated` | inside `sizeof`, `decltype`, `_Alignof`, `noexcept(...)` | side-effect and data-flow rules |
| `in_discarded` | in a discarded `if constexpr` branch | unreachable-code rules |

## 3. Layer `tok`: tokens and comments

Needed by 31 rules (comments, literal spellings, escapes, trigraphs, digraphs,
spliced lines, braces) and by the metrics.

```
Token    { id, kind: identifier|keyword|literal|punctuator|header_name|other,
           spelling: string, pos: Range, file: FileId,
           flags: { at_line_start, after_splice, from_trigraph, digraph } }
Literal  { token: TokenId, kind: integer|floating|character|string|user_defined,
           prefix: ""|u8|u|U|L, suffix: string, base: 8|10|16|2,
           escapes: [Escape], value: ConstValue? }
Escape   { offset, kind: simple|octal|hex|universal, text, terminated_by: end|escape|other }
Comment  { id, kind: line|block, range: Range, text: string,
           contains: { block_open, line_comment_marker, splice_at_end } }
```

- The token stream is the one before macro expansion (as written), per file, so
  rules about spelling (OC-0022 terminated_escape, OC-0143 no_spliced_macro,
  OC-0182 integer_constant_macro_form) and the token metric (OC-0389) read the
  source as the reader sees it.
- Commented-out code detection needs `Comment.text`; the rule parses it itself.

## 4. Layer `pp`: preprocessor events

Needed by 56 rules. The preprocessor must be recorded, not just run.

```
Include   { id, file: FileId, pos, spelling: string, angled: bool,
            target: FileId?, resolved_path, guard: MacroId?, in_block: bool,
            preceded_by_code: bool }
MacroDef  { id, name, pos, function_like: bool, params: [string], variadic: bool,
            body: [TokenId], kind: define|undef, file: FileId,
            predefined: bool, command_line: bool }
MacroExp  { id, macro: MacroDefId, call: Range, args: [Range],
            parent: MacroExpId?, uses_stringize: bool, uses_paste: bool,
            in_directive: bool }
Cond      { id, kind: if|ifdef|ifndef|elif|elifdef|elifndef|else|endif,
            pos, condition_tokens: [TokenId], value: bool?, evaluated: bool,
            undefined_identifiers: [string], group_taken: bool, match: CondId }
Pragma    { pos, tokens: [TokenId] }
Directive { pos, kind: line|error|warning|null|unknown, tokens: [TokenId] }
```

- `MacroExp.parent` gives the nesting of expansions, so a rule can tell `assert(x)`
  written by the user from the same tokens inside another macro.
- `Cond.undefined_identifiers` answers "identifier in `#if` that is not defined"
  directly; `value` and `evaluated` the rules on constant `#if` and on groups that
  are never taken.
- `Include.preceded_by_code` is computed from the token stream, for "includes only
  at the top".

## 5. Layers `ast` and `sem`: declarations, types, statements, expressions

`ast` (151 rules) and `sem` (174 rules) share one structure. `sem` rules additionally
read the semantic fields (types, conversions, constant values, resolved
declarations). A frontend that cannot fill the `sem` fields cannot serve those rules,
which is the reason the libclang C API is not enough (see `architecture.md`).

### 5.1 Types

```
Type { id, kind, quals: {const, volatile, restrict, atomic},
       canonical: TypeId, sugar: TypeId?,       # typedef / alias chain kept
       name: string?, decl: DeclId?,           # for typedef, record, enum
       size: u64?, align: u32?,                # target values, null if incomplete
       complete: bool,
       # by kind
       int:     { signed: bool, width: u16, plain_char: bool, is_bool: bool }
       float:   { width: u16, complex: bool }
       pointer: { pointee: TypeId }, reference: { target: TypeId, rvalue: bool }
       array:   { element: TypeId, size: u64?, vla: bool, flexible: bool }
       function:{ result: TypeId, params: [TypeId], variadic: bool,
                  prototype: bool, noexcept: ExceptSpec, ref_qual: none|lvalue|rvalue }
       record:  { tag: struct|union|class, layout: Layout?, polymorphic: bool,
                  abstract: bool, trivial: bool, aggregate: bool, final: bool }
       enum:    { underlying: TypeId, scoped: bool, fixed: bool }
       member_pointer: { class: TypeId, pointee: TypeId }
       template_param, dependent, auto, nullptr, void }
Layout { fields: [{ decl: DeclId, offset_bits: u64, width_bits: u32 }],
         padding_bytes: u32, has_padding: bool }
```

- `sugar` keeps typedefs and aliases. Rules that say "also through typedefs" use
  `canonical`; rules about the spelled type (`bitfield_type`, `int` versus a size
  typedef) use the sugared type.
- `Layout.has_padding` answers OC-0428 no_padding_compare without the rule computing
  layout.

### 5.2 Essential type

The essential type model (`catalog/CONCEPTS.md`) is computed by Oculus, not by the
frontend, from the expression tree and constant values:

```
Essential { category: boolean|character|signed|unsigned|enum|floating|other,
            width: u16, enum_type: TypeId?, from_constant: bool }
```

It is stored per expression node (`Expr.essential`) because 40 rules of chapter 8
read it, and many of them read it for the operands of the same operator.

### 5.3 Declarations

```
Decl { id, kind, name: string, qualified_name: string, pos: SrcPos,
       name_pos: Range, origin,
       type: TypeId, scope: ScopeId, parent: DeclId?,
       linkage: none|internal|external|module,
       storage: static|thread|automatic|dynamic|register|none,
       is_definition: bool, first_decl: DeclId, redecls: [DeclId],
       is_inline, is_constexpr, is_extern_c, is_used: bool, is_referenced: bool,
       attributes: [Attr], access: public|protected|private|none,
       # by kind
       var:      { init: NodeId?, init_style: none|copy|direct|list,
                   is_param: bool, param_index: u16 }
       function: { params: [DeclId], body: NodeId?, is_main, is_virtual,
                   is_pure, is_override_marked, is_final, is_deleted, is_defaulted,
                   is_implicit, overrides: [DeclId], except: ExceptSpec,
                   special: none|default_ctor|copy_ctor|move_ctor|copy_assign|
                            move_assign|dtor|conversion|operator, operator: OpKind?,
                   explicit: bool, ref_qual, member_inits: [MemberInit],
                   try_block: NodeId? }
       field:    { bit_width: u32?, is_mutable: bool, default_init: NodeId? }
       record:   { bases: [Base], members: [DeclId], friends: [DeclId] }
       enum:     { enumerators: [DeclId] }, enumerator: { value: ConstValue, explicit: bool }
       typedef, label: { uses: [NodeId] }, namespace: { anonymous: bool, inline: bool }
       template: { params: [DeclId], pattern: DeclId, specializations: [DeclId],
                   explicit_instantiations: [Range], instantiations: [DeclId] }
       using, using_directive, static_assert, concept }
Base       { type: TypeId, virtual: bool, access, pos }
MemberInit { member_or_base: DeclId|TypeId, init: NodeId, written: bool }
ExceptSpec { kind: none|noexcept|noexcept_false|noexcept_expr|throw_list|throw_any,
             types: [TypeId] }
Scope      { id, kind: file|namespace|function|block|class|prototype|for_init,
             parent: ScopeId?, decls: [DeclId] }
```

- `Scope` exists because the shadowing and name rules (chapter 5) compare names
  along the scope chain.
- `is_used`/`is_referenced` are per TU; the project-wide "unused" rules decide in
  phase 2 (section 8).

### 5.4 Statements and expressions

One node table for both, a tree per function body (and per global initialiser):

```
Node { id, kind: NodeKind, pos: SrcPos, origin, parent: NodeId?, children: [NodeId] }
```

Statements carry their structure in named children (`if.cond`, `if.then`,
`if.else`, `for.init`, `for.cond`, `for.step`, `for.body`, `switch.cases`, `case.value`,
`try.handlers`, `handler.type`, `goto.label`, `return.value` ...). An `else if` is an
`if` whose `else` child is an `if` and is flagged `else_if: true`.

Two facts every structural rule needs (built: `src/ir/nodes.aiml`):

- `has_skipped_code` on a `switch`, an `if` and a function body: the preprocessor
  skipped an `#if` branch inside it. The node shows one configuration of the build;
  another one may have more `case` labels, a `default`, an `else` or the `goto` of
  a label. Rules about the shape of such a statement do not judge it.
- A node written in a macro body is reported at its spelling (the `#define`), once,
  not at every expansion (`written_pos` in `src/rules/rule_kit.aiml`). A binary
  operator whose operator token is in the macro body and whose operands are macro
  arguments sits at the operator.

Expressions add:

```
Expr { type: TypeId, value_category: prvalue|lvalue|xvalue,
       implicit: [Conversion],         # applied to this expression, in order
       constant: ConstValue?,          # if it is a constant expression
       essential: Essential?,          # section 5.2
       side_effects: none|local|persistent,
       # by kind
       ref:    { decl: DeclId }                      # names an entity
       call:   { callee: DeclId?, through_pointer: bool, virtual: bool,
                 args: [NodeId], builtin: string? }
       op:     { op: OpKind, overloaded: DeclId? }   # unary, binary, compound, ?:
       cast:   { kind: c_style|functional|static|reinterpret|const|dynamic|implicit,
                 conversion: ConversionKind, written_type: TypeId }
       member: { base: NodeId, decl: DeclId, arrow: bool }
       literal:{ token: TokenId }, lambda: { captures: [Capture], body: NodeId }
       new/delete: { array, placement: [NodeId], type: TypeId },
       throw:  { operand: NodeId? }, sizeof/alignof, generic_selection, init_list ... }
Conversion { kind: lvalue_to_rvalue|integral_promotion|integral|floating|
             float_integral|pointer|null_pointer|array_decay|function_decay|
             qualification|boolean|derived_to_base|user_defined|...,
             to: TypeId, narrowing: bool }
ConstValue { kind: int|float|string|null|bool, int: i128?, float: f64?,
             text: string? }
```

- `implicit` is the decisive field. The rules on implicit conversions (OC-0070 to
  OC-0076, OC-0440 and the others) read the conversion list of each operand; nothing
  else exposes them.
- `constant` is filled for every constant expression, so "constant in range" checks
  (OC-0199 ctype argument, the good cases with `' '`) need no evaluator in the rule.
- `side_effects` uses the definition of a persistent side effect from
  `catalog/CONCEPTS.md`; calls count as persistent unless the library model or phase 2
  says the callee is pure.

## 6. Layer `cfg`: control flow per function

Needed by 22 rules directly, and by every `dfa` rule underneath.

```
Cfg      { function: DeclId, entry: BlockId, exit: BlockId, blocks: [Block] }
Block    { id, elements: [NodeId], terminator: NodeId?,
           succ: [Edge], pred: [BlockId], reachable: bool }
Edge     { to: BlockId, kind: normal|true|false|case|default|exception|
           noreturn|back, value: ConstValue? }
```

- Built by Oculus from the node tree, not taken from the frontend; so it exists for
  every frontend and stays valid after the AST is dropped.
- `exception` edges from calls that may throw (by `ExceptSpec` and the library model)
  to the handlers, for chapter 17. `noreturn` edges for `abort`, `exit` and functions
  declared `noreturn`.
- `reachable` is computed with constant conditions (`Edge.value`), so
  `while (1)` and `if (0)` are handled, and blocks in `in_discarded` code are left
  out.
- Metrics (OC-0382 complexity) do not use the CFG; they count decision nodes of the
  tree as written (see the rule), which keeps macros out.

## 7. Layer `dfa` and `lib`: flow facts and library models

### 7.1 Flow facts

Computed on the CFG by Oculus' analyses in the thread pool. They are results, not
input from the frontend:

```
DefUse      { var: DeclId, defs: [NodeId], uses: [{ node: NodeId, reaching: [NodeId] }] }
ValueRange  { node: NodeId, min, max, may_be_null: bool, known_null: bool }
PointsTo    { node: NodeId, targets: [{ object: ObjectId, offset_range }],
              unknown: bool }
Object      { id, kind: variable|heap|string_literal|static_buffer|param_target,
              decl: DeclId?, alloc_site: NodeId?, size: u64?, storage }
State       { object: ObjectId, block: BlockId, machine: string, states: [string] }
```

- `State` is a generic typestate result: the library model (7.2) defines small state
  machines (`allocated → freed`, `open → closed`, `unlocked → locked`,
  `valid → moved_from`, `errno: stale → reset → set → tested`), the analysis tracks
  them per object and path. A large part of the 98 `dfa` rules are such typestate
  checks (resources, streams, mutexes, errno, move); the others use `DefUse`,
  `ValueRange` and `PointsTo`.
- Every result has a precision flag: `must` (on every path) or `may` (on some path).
  Rules with `undec` report only `must` facts by default, which is the main switch
  against false positives; `may` findings are a configurable stricter mode.

### 7.2 Library model

Data, not code, kept in the catalogue repository (`catalog/lib/*.json`, to be
written), keyed by function or macro name and header:

```
LibFunction { name, headers: [string], languages, from_standard,
              banned_by: [rule id],           # 13.2 / 13.3 banned lists
              sets_errno: always|on_error|never, errno_only_error: bool,
              returns: { resource: memory|stream|thread|mutex|..., null_on_failure: bool,
                         static_buffer: string?, const_result: bool }?,
              releases: { param: u8, resource }?,
              params: [{ string: bool, writes: bool, size_of: u8?, range: [min,max]?,
                         format: printf|scanf|none, callback: pure|any }],
              thread_safe: bool, blocking: bool, may_throw: bool, noreturn: bool,
              macro_may_double_eval: [u8] }
```

- One entry carries everything the rules ask about one function: `getenv` has
  `const_result`, `static_buffer: "environment"`, `thread_safe: false`; `fopen` has
  `returns.resource: stream`; `getc` has `macro_may_double_eval: [0]` (OC-0434).
- The C++ library parts (smart pointers, `std::move`, containers, algorithms with
  predicates) get the same treatment (`LibClass`, `LibFunctionTemplate`).

## 8. Layer `xtu`: phase 2 facts

Needed by 45 rules. Every TU worker writes these records; phase 2 merges them by
entity key. They are the only data that leaves the TU.

```
EntityKey = qualified name + kind + (for functions) mangled or canonical signature
Fact kinds:
  declared   { key, pos, linkage, type_text, is_definition, is_inline, file, header }
  used       { key, pos, kind: read|write|call|address|odr_use }
  call       { caller: key, callee: key | indirect, pos, may_throw: bool }
  throws     { function: key, types: [type_text], escapes: bool }
  instantiated { template: key, args_text, pos }
  macro      { name, pos, defined_in: file }
  tag        { name, pos, kind }
  thread_entry { function: key, created_at: pos }
  lock       { function: key, mutex: key, held: [key], pos }
  resource   { function: key, effect: acquire|release|persistent_side_effect }
```

- Format: one JSON object per line (JSON Lines), one file per TU, so that a crashed
  worker leaves the facts of the other TUs usable and the files can be inspected by
  hand. A binary form can follow if size becomes a problem.
- Rules in phase 2 see only facts, never another TU's IR; that keeps the memory
  bound at one TU plus the merged fact store.

Result of the check: every one of these rules can be written as a query on the tables
above, and in every row the good case is excluded by a field of the format (origin,
sugar chain, constant value, conversion kind, scope, flow fact or library model), not
by a heuristic in the rule. Some fields exist only because a rule needs them, for
example `Include.preceded_by_code`, `Literal.escapes[].terminated_by` and
`Layout.has_padding`; without them the rules would re-tokenise source text or compute
layouts themselves.

## 10. What the frontend has to deliver

Only layers 2 to 5: files, tokens, comments, preprocessor events, types,
declarations and the node tree with types, implicit conversions and constant values.
Layers 5.2 (essential types), 6 (CFG), 7 (flow facts) and 8 (phase 2 facts) are
computed by Oculus from that. So the binding question (`architecture.md` section 2)
becomes: which binding can fill `Expr.implicit`, `Expr.constant`, `Type.sugar`,
`Layout` and the `pp` events completely. The libclang C API cannot fill
`Expr.implicit`; that remains the reason for the LibTooling worker.

## 11. Implemented so far

The first slice runs end to end for OC-0040 bitfield_type (C and C++):

- `worker/oculus_clang.cpp` fills files (2.2, `kind` only), types (5.1: kind, name,
  canonical, one sugar step, typedef or tag declaration, the builtin integer fields,
  `is_dependent`) and declarations (5.3: kind, name, `SrcPos`, origin, type, parent,
  definition, bit-field width, the written type specifiers). Declarations of system
  headers are added only when a type refers to them.
- `src/ir/` holds the same records as AIML models; `RuleInformation` is their
  container and `IrUnit.info` carries it to the rules.

Three fields were missing in the draft above and were found by implementing the rule:

- `IrDecl.written_builtin` and `IrDecl.sign_written`: plain `int` and `signed int`
  are one type; only the spelling of the declaration (or of the typedef that finally
  spells the builtin type) tells them apart. `Type.sugar` alone is not enough.
- `IrDecl.instantiation_pos`: a declaration inside a template instantiation is
  reported at the point of instantiation, so the record has to carry it.
- `IrType.is_dependent`: the template pattern itself must not be checked; its
  instantiations are.

Built since then, rule by rule (the models in `src/ir/` are the reference):

- Statements and expressions (5.4) as one node table `IrNode` with the facts the
  statement rules need (`has_skipped_code`, switch label counts, the default's place,
  operator and cast spelling), see the note after 5.4.
- The preprocessor (4) as `IrMacro`: one record per `#define`, `#undef` and
  `#pragma`/`_Pragma` of active code outside system headers, collected by
  `PPCallbacks` while Clang parses (`worker/unit_tables.h`, `MacroCollector`). A
  define carries its body as spelled tokens, the parameter facts, the `#` and `##`
  operators with their positions, and whether it uses the call site (`__FILE__`,
  `__LINE__`, `__func__`, or a macro that does); an undef the file of the definition
  it removes. Expansions and conditions (`MacroExp`, `Cond`) are not recorded yet.
- `IrFile.include_guarded` for headers: Clang's multiple-include optimisation (an
  `#ifndef` guard around everything, or `#pragma once`), or else a raw-token check
  that every piece of code sits in some guard block (amalgamated headers have
  several). Code in a skipped `#if` does not count, a header of directives only is
  harmless. `included_in_declaration` marks data and X-macro files included in the
  middle of an enum, an initializer or a namespace.
- `IrDecl.declarator_pos` and `IrDecl.group_uid` for variables and fields: where the
  declarator starts (the first `*`, `&` or `(`, else the name), and the uid of the
  first declarator of the same declaration. Clang keeps the declarators of
  `int a, b;` as separate declarations with one begin location; the group compares
  that location raw, so two declarations made by two expansions of one macro stay
  apart, which source positions alone cannot do.
- `IrDecl.odr_definition`: a function or variable definition with external linkage
  that every including file would repeat. Clang decides inline (also implicit:
  in-class members, constexpr), templated, deleted, defaulted, weak, tentative and
  specialized; the rule only adds "written in a header".
- `IrDecl.paren_declarator`: a local `T (name);`, which Clang parses as a
  declaration of `name` although it reads as a conversion.
- `IrDecl.in_extern_c` also holds for a tag first named inside an `extern "C"`
  block (`typedef struct x x;`), whose semantic scope is the enclosing namespace.
- `IrMacro` records of kind `include` (the header name as written, read from the
  directive line of the file Clang entered) and `expansion` (a macro of a system
  header expanded in the user's code, such as `NULL`, `errno` or `offsetof`, at
  the place its name is spelled). Expansions of the user's own macros are not
  recorded; there are too many of them in macro-heavy code.
- A `CXXCatchStmt` node carries the caught type (`type_uid`) and the handler's
  declaration (`ref_uid`).
- `IrNode.spelling` (literals as written, for octal, suffix and escape rules),
  `IrNode.role` (`then`, `else` or `body` under an if, loop or switch; an omitted
  implicit cast passes its role to its operand) and `IrNode.before` (for an empty
  statement, the character before it on its line).
- `IrDecl.is_explicit`, `is_deleted`, `is_defaulted` and `min_args` for
  constructors and other functions.
- `IrMacro.splice_pos`: the first backslash continuation of a #define; an
  include record's `name_pos` is its header name.
- For the metric rules: `IrFile.line_classes` (one character per physical line,
  `b` blank, `c` comment only, `x` code only, `m` both, from the raw tokens of the
  file with comments kept; code in `#if 0` counts as code), `IrDecl.def_begin`,
  `body_end` and `body_tokens` for function definitions (lambdas belong to their
  enclosing function), and `IrNode.macro_body` (the node's keyword or operator
  comes from a macro body, so it is not part of the source as written).
- `IrFile.lexical_marks`: what the raw tokens and characters of a user file show,
  as `code:line:col;` entries: `comment_open` (a `/*` inside a block comment),
  `comment_splice` (a line comment continued by a backslash), `trigraph`,
  `open_escape` (at a literal whose octal or hex escape runs into a plain
  character), `odd_escape` (an escape the standard does not define, at the
  backslash) and `digraph` (adjacent digraphs such as `<::>` give one mark).  Literals in skipped code and on `#include`,
  `#error` and `#warning` lines are not looked at.
- `IrDecl.array_param` and `static_array_pos` for parameters written as arrays;
  `IrNode.detail` of `sizeof` (`sizeof` or `sizeof_type`), of `typeid`
  (`type`, `expr` or `polymorphic`, the evaluated form) and of `delete`
  (`incomplete` when it destroys an incomplete class).
- `IrDecl.copy_or_move`, `align_count`, `second_align_pos` and
  `zero_align_pos`; `IrNode.role` also `init` and `step` (the init statement
  of for, if and switch, the increment of for); a `_Generic` with only a
  default association has detail `default_only`, a default between other
  associations gets a marker node `GenericDefaultMiddle` at `default`.
- `IrDecl.pointer_pos` (the * of a written pointer declarator); `IrNode.side_effect` for sizeof and alignof; a range-based for gets a marker
  node `RangeInitCalls` at its range expression, the detail being the number of
  function calls written there.
- `IrDecl.ref_qualifier`, `returns_kind`, `is_referenced`, `maybe_unused`,
  `named_in_body` (a parameter's name among the raw tokens of the body);
  `name_count`, `special_local`, `abstract_public_copy`,
  `template_ctor_no_copy`, `template_assign_no_copy`, `may_throw`,
  `pure_overrides_impl` and `default_arg_pos` for the class and override rules;
  `IrNode.detail` `placement` (placement new other than nothrow), `destructor`
  (an explicit destructor call), `operator_new_delete` (operator new or delete
  called as a function); a marker node `RawSmartPointer` at the raw pointer
  argument of a std::shared_ptr or std::unique_ptr constructor or reset.

## 12. Notes on the AIML side

- Returning an element of a `list<Model>` by value from a function (`return: { at:
  [list, idx] }`, also through a local copy) corrupts the strings of the list element
  with the aiml build pinned in CI: the copy is dropped without the strings having
  been retained. Rules therefore read records inline as `ref<...>` borrows after a
  bounds check (`info_has_type`, `info_has_decl`). To be reported upstream.
